# Cybersecurity สำหรับโปรเจกต์นักศึกษา

## 1. เริ่มจาก threat modeling

ก่อนเขียนระบบ ให้ตอบ: - อะไรคือทรัพย์สินสำคัญ เช่น API token, ข้อมูลผู้ใช้,
คำสั่งควบคุม - ใครอาจเข้าถึงโดยไม่ได้รับอนุญาต - ช่องทางโจมตีคืออะไร เช่น เว็บ, MQTT,
USB, ไฟล์อัปโหลด - ผลกระทบคืออะไร - มาตรการใดลดความเสี่ยงได้

ใช้แนวคิด least privilege: ให้แต่ละส่วนมีสิทธิ์เท่าที่จำเป็น

## 2. จัดการ secret

-   เก็บ key ใน environment variable หรือ secret manager
-   ใส่ `.env` ใน `.gitignore`
-   แจกไฟล์ `.env.example` ที่มีแต่ชื่อ variable ไม่มีค่าจริง
-   หาก key หลุด ให้ revoke/rotate ไม่ใช่แค่ลบจากไฟล์ล่าสุด
-   อย่าใส่ secret ในภาพหน้าจอหรือ log

## 3. ตรวจ input และไฟล์อัปโหลด

ไฟล์ที่ผู้ใช้อัปโหลดอาจมีขนาดใหญ่ ชื่อแปลก หรือเนื้อหาที่เป็นอันตราย: - จำกัดขนาดไฟล์ -
อนุญาตเฉพาะชนิดที่จำเป็น - สร้างชื่อไฟล์ภายในระบบ ไม่เชื่อ path จากผู้ใช้ - ป้องกัน path
traversal เช่น `../../secret.txt` - อย่ารันไฟล์ที่อัปโหลดเป็นโปรแกรม -
แยกโฟลเดอร์ข้อมูลออกจาก source code

## 4. Password และ authentication

ห้ามเก็บรหัสผ่านแบบ plain text หรือ hash ด้วย MD5/SHA-1 แบบตรง ๆ สำหรับระบบบัญชี
ใช้ password hashing ที่ออกแบบเฉพาะ เช่น Argon2id หรือ bcrypt
ผ่านไลบรารีที่เชื่อถือได้ และใช้ session/token ที่มีอายุและการเพิกถอนเหมาะสม

## 5. ความปลอดภัย MQTT/IoT

-   ปิด anonymous access ใน broker ที่ใช้งานจริง
-   ใช้บัญชีแยกสำหรับแต่ละ device
-   จำกัด ACL ให้ publish/subscribe เฉพาะ topic ที่จำเป็น
-   ใช้ TLS เมื่อผ่านเครือข่ายที่ไม่เชื่อถือ
-   ป้องกัน replay ด้วย timestamp, nonce หรือ command expiry ตามระบบ
-   ห้ามให้ message จาก dashboard ข้ามกลไก safety ของอุปกรณ์

## 6. การอัปเดต dependency

-   ใช้ virtual environment
-   ตรวจ dependency และแหล่งที่มา
-   pin เวอร์ชันเมื่อจำเป็นเพื่อ reproducibility
-   ทดสอบก่อนอัปเดตไลบรารีสำคัญ
-   สำรองข้อมูลก่อน migration

## 7. Logging และ incident response

บันทึกเหตุการณ์ login, permission denied, config changes และ error ที่จำเป็น
โดยไม่เก็บ secret ข้อมูลส่วนตัวเกินจำเป็น วางแผนตอบสนอง: 1.
จำกัดผลกระทบ/แยกอุปกรณ์ที่มีปัญหา 2. เก็บหลักฐาน log อย่างปลอดภัย 3. เปลี่ยน
credential ที่อาจรั่ว 4. ตรวจต้นเหตุและขอบเขต 5. แก้ไขและทดสอบ 6.
บันทึกบทเรียนเพื่อป้องกันซ้ำ

## 8. ขอบเขตการทดสอบ

ทดสอบเฉพาะระบบที่ตนเองเป็นเจ้าของหรือได้รับอนุญาตเป็นลายลักษณ์อักษร
หลีกเลี่ยงการสแกนหรือทดลองกับเครือข่ายของบุคคลอื่น ใช้เครื่องจำลองหรือ lab
ที่แยกจากระบบจริง

## โปรเจกต์จบ

ทำ security checklist สำหรับ IoT dashboard พร้อม threat model,
role/permission matrix, secret handling, validation, log policy
และการทดลองกรณีเข้าถึงข้อมูลที่ไม่ได้รับอนุญาตใน lab ของตนเอง
